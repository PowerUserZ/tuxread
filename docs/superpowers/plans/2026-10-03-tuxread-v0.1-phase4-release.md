# TuxRead v0.1 — Phase 4: CI and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make TuxRead v0.1 releasable. GitHub Actions checks every change, fuzzes every night, and on a tag builds the installer and the portable zip for x64 and ARM64, with checksums and the third-party license texts. The app reports a missing WebView2 runtime. Both programs carry their version. The follow-ups that earlier reviews left for this phase are fixed.

**Architecture:**
- **Policy files at the root:**
  - `deny.toml` is the dependency policy: licenses and RustSec advisories, for `cargo deny`.
  - `about.toml` and `about.hbs` drive `cargo about`.
  - `scripts/third-party-licenses.mjs` joins the Rust license texts with those of the npm packages that the window bundles, into `THIRD-PARTY-LICENSES.txt`. It is a release-time file, never committed.
- **One version:** `Cargo.toml`'s workspace version is the only one. `tauri.conf.json` has none, so Tauri takes Cargo's. `package.json` repeats it for About, and a test keeps the two equal.
  - `TuxRead.exe` gets its version resource from Tauri.
  - `tuxread-cli.exe` gets its version resource from `tauri-winres`, in `crates/cli/build.rs`.
- **WebView2 check:** `run()` asks `tauri::webview_version()` first. Without a runtime it shows a native message box (`tuxread_win::show_error`) and exits with 1.
- **Packaging:**
  - `src-tauri/tauri.release.json` turns on the NSIS bundle: per user, with the WebView2 bootstrapper embedded, English and Turkish, with the license files.
  - `scripts/package.ps1` makes the release files of one architecture.
  - `scripts/check-release.ps1` checks them, and in CI also installs, starts and uninstalls.
- **Three workflows:**
  - `ci.yml` runs on pushes to `main` and on pull requests:
    - the corpus, made on Linux and cached by its scripts' hash;
    - a Linux job: clippy, tests and `cargo deny`;
    - a Windows x64 job: every check, the real-disk test, the WebView2 check and the window's smoke test.
  - `fuzz.yml` fuzzes the three targets every night, and for as long as asked when run by hand.
  - `release.yml` runs on `v*` tags and by hand. It builds, packages and checks each architecture on its own runner. On a tag it then makes a draft release.

## Spec refinements made while planning

The spec is the authority. These are implementation decisions it leaves open or states differently, each with its reason; read them before Task 1.

1. **`cargo deny` runs in the Linux job, not the Windows one** (§7.6 lists it under Windows x64).
   - Its GitHub action is a container action, and containers run only on Linux runners.
   - `deny.toml`'s `[graph] targets` names the Windows targets, so the check covers exactly the dependencies Windows builds use. It also covers Linux, where the CLI and the engine are tested.
2. **The license policy** (§5.4 says GPL, LGPL and AGPL are never accepted).
   - `deny.toml` accepts the permissive licenses that the dependency graph uses, plus MPL-2.0. MPL-2.0 is file-level copyleft, and its crates (`option-ext`, and `cssparser` and `selectors` at build time) are used unmodified from crates.io.
   - **"Unmaintained" advisories fail only for crates the workspace uses directly.** `bincode` (via `mbrman`), the `unic-*` crates and `proc-macro-error` (via Tauri) are flagged unmaintained. None has a vulnerability, and replacing them is their dependents' work.
   - Vulnerabilities fail for every crate.
3. **`THIRD-PARTY-LICENSES.txt` is made at release time, not committed.**
   - It covers every Rust crate in the shipped Windows binaries, without build and dev dependencies.
   - It also covers every npm package that the window bundles: the packages in `package-lock.json` that are neither dev nor optional.
   - Each license file is copied as it is.
4. **The installer installs the window; the command line ships in the portable zip.** The CLI needs a console and a folder on `PATH`. A per-user installer that edits `PATH` is more than v0.1 needs.
5. **The installer speaks English and Turkish**, like the window. Tauri's default `installMode`, `currentUser`, gives a per-user install with no UAC prompt. `scripts/check-release.ps1` checks that the installer's manifest asks for no elevation.
6. **The WebView2 message is in both languages at once.** It appears before the window exists, and the window is where the language is chosen.
7. **The version lives in `Cargo.toml` and `package.json`**; `tauri.conf.json` has none.
   - About reads it from `package.json`.
   - The executables, the installer and the diagnostics read it from Cargo.
   - A test fails when the two differ.
8. **A release is a draft until the maintainer publishes it.**
   - The workflow refuses a tag that is not `v` plus the version.
   - Run by hand, it builds and checks everything, but makes no release: the files stay as the run's artifacts. This is the dry run in the release checklist.
9. **Fuzzing runs nightly for 20 minutes per target.** A run started by hand takes the length as input. v0.1's one-hour gate (§8) is a step of the release checklist: a manual run with `seconds = 3600`.
10. **The window's smoke test runs in CI** (Phase 3's refinement 8 had kept it local).
    - The `windows-2025` runner has an interactive desktop session, so WebView2 opens the window.
    - CI runs the `harden`, `browse` and `copy` scenarios on every change, with the corpus's 10,000-entry image.
    - `disk` stays a release-checklist step. It needs a UAC prompt, and on the elevated runner the window reads disks without the helper. `scripts/check-no-webview2.ps1` runs in CI too.
11. **The smoke test lets WebView2 choose its DevTools port** and reads it from `DevToolsActivePort` in the throwaway profile. A fixed port fails whenever something else holds it, such as the last scenario's WebView2 while it exits.
    - **WebView2 ignores `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` in an elevated process**, and every process on the CI runner is elevated.
    - So the CI build of the window asks for the port in its own configuration (`additionalBrowserArgs`, merged with `--config`).
    - Release builds never have a DevTools port.
12. **Not in this phase**, from the earlier final reviews:
    - **The pipe's create-instance right** (Phase 2). Another process of the same user could add pipe instances. Denying the right to the user would deny it to the elevated helper, which runs as the same user. The client's server-PID check limits the attack to denial of service, which §5.7 accepts.
    - **The save dialog in Rust** (Phase 3). `save_report` takes the path from the window. Moving the dialog to Rust is defense in depth: §5.8 already keeps any script but TuxRead's own out of the window.
    - **Probing outside the registry lock** (Phase 3). While a disk is probed, other commands wait; nothing freezes.
    - **`aria-activedescendant` for one frame** (Phase 3). It can name a row that is not rendered yet, for one frame.
    - **A stale listing after the helper ends** (Phase 3). If another locked disk is opened first, the old listing stays until a click on it says "not found". There is no reliable automated test for it yet.
    - **Phase 1's CLI and report edge cases.**
      - A source path with a trailing `/` makes a folder named `_`.
      - `/` given with other sources, and Overwrite onto a file inside a copied folder, give odd report lines.
    - **Phase 2's test-harness gaps.**
      - The custom harness prints "ok" for a skipped real-disk test.
      - Tests outside `within` have no timeout.
      - The image-path check has no mutation test.
      - `describe()` drops a disk when only `StorageDeviceProperty` fails.
      - The parent PID could be reused during the UAC prompt.

## Global Constraints

- **Licensing:**
  - All project code is MIT OR Apache-2.0.
  - The one new dependency is `tauri-winres` (MIT), a Windows build dependency of `tuxread-cli`. It is pinned like the Tauri crates: `tauri-winres = "=0.3.6"`.
  - Dependencies may use only the licenses `deny.toml` accepts. GPL, LGPL and AGPL are never accepted (§5.4).
- **Rust:** edition 2024; workspace `rust-version = "1.89"`; stable toolchain. Only the fuzz targets use nightly.
- **No network in the app** (§5.8, §9):
  - no telemetry, no update checks;
  - the WebView2 message names the download address but opens nothing.
- **Workflows:**
  - `permissions: contents: read`, except the release's draft job, which has `contents: write`.
  - No secrets other than the workflow's own `GITHUB_TOKEN`. v0.1 is unsigned.
  - Every `cargo build`, `test`, `clippy`, `install` and `about generate` in a workflow passes `--locked`. `cargo fuzz run` builds the `fuzz` crate against its own committed `Cargo.lock`.
- **Version:** only `Cargo.toml` (`[workspace.package] version`) and `package.json` carry it (refinement 7).
- **Release files** (§9): for each of `x64` and `arm64`:
  - `TuxRead-<version>-<arch>-setup.exe`
  - `TuxRead-<version>-<arch>-portable.zip`
  - `TuxRead-<version>-<arch>.sha256`, in `sha256sum` format with LF line endings
- **The code signing policy text** goes into the README and the release notes word for word, as spec §9 gives it.
- **Line endings:** LF in the repository (`.gitattributes`).
- **Git:**
  - Work on `feat/v0.1-phase4-release`, branched from `main` at `f6c81c7`.
  - Commits are local. Pushing, the pull request, tags and releases are the maintainer's call. CI first runs on the pull request.
  - End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Shell:**
  - Windows 11 with Git Bash and PowerShell 7 (`pwsh`), as in Phase 3.
  - Run the smoke test, the PowerShell scripts and anything that sets a UNC path in an environment variable from PowerShell.
  - The corpus is at `\\wsl.localhost\Ubuntu-26.04\var\tmp\tuxcorpus` (Phase 1's `scripts/make-corpus.sh`).
- **Formatting:**
  - Run `cargo fmt --all` before every commit.
  - Every other file is formatted as its block below shows, with lines up to 120 columns.
- **The smoke test and the WebView2 check open windows.** Do not touch the mouse or keyboard while they run.
- **Installs:**
  - `cargo-deny` and `cargo-about` are installed on the dev machine with `cargo install --locked` (Task 1).
  - `scripts/check-release.ps1 -Install` installs and uninstalls TuxRead for the current user. Run it locally only on a machine where that is fine.

## Review Focus

The spec implies these five conditions, and the happy-path tests would not exercise them. Each has a test in the task that owns the code:

1. **A user profile or install folder with spaces and non-ASCII letters**, such as `C:\Users\Şükrü Yılmaz`. TuxRead's users are often Turkish. The installer must install there, the window must start from there, and the elevated helper must start from there.
   - `scripts/check-release.ps1 -Install` installs into `%TEMP%\Şükrü Yılmaz\TuxRead` and starts the installed program (Task 8, and CI in Task 11).
   - The helper was started from such a folder while planning (Provenance).
2. **A standard user runs the installer.** They expect no UAC prompt and an install for their account only. `scripts/check-release.ps1` checks that the installer's manifest says `asInvoker` (Task 8).
3. **A PC without the WebView2 runtime starts the portable `TuxRead.exe`.** They expect a message that says what is missing and where to get it, not a process that runs with no window.
   - `scripts/check-no-webview2.ps1` (Task 3).
   - CI runs it on every change (Task 9).
4. **A tag that does not match the version**, such as `v0.1.1` pushed before the version was bumped. No release may come of it. The workflow's first step refuses it, and Task 11 runs that step against a wrong tag.
5. **A downloaded file checked with standard tools.** `sha256sum -c` (Git Bash, Linux) and `Get-FileHash` must agree with the `.sha256` file.
   - Task 8 runs `sha256sum -c` on the local release files.
   - The release workflow runs it on the downloaded artifacts before it drafts the release (Task 11).

- [ ] **Step 5: Write the license script, and run it before cargo-about has a configuration**

`scripts/third-party-licenses.mjs`:

```js
// Writes THIRD-PARTY-LICENSES.txt, which ships next to TuxRead.exe: the license texts of every
// Rust crate in the Windows builds (cargo-about, with about.toml and about.hbs) and of every npm
// package in the window's bundle (package-lock.json entries that are neither dev nor optional).
// Usage: node scripts/third-party-licenses.mjs <output file>
import { execFileSync } from "node:child_process";
import { mkdtempSync, readFileSync, readdirSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

const root = join(import.meta.dirname, "..");
const out = process.argv[2];
if (!out) {
  console.error("usage: node scripts/third-party-licenses.mjs <output file>");
  process.exit(2);
}

// cargo-about refuses to write to a redirected stdout on Windows, so it writes a file.
const work = mkdtempSync(join(tmpdir(), "tuxread-licenses-"));
const rustFile = join(work, "rust.txt");
execFileSync("cargo", ["about", "generate", "--locked", "about.hbs", "-o", rustFile], { cwd: root, stdio: "inherit" });
const rust = readFileSync(rustFile, "utf8");
rmSync(work, { recursive: true, force: true });

const lock = JSON.parse(readFileSync(join(root, "package-lock.json"), "utf8"));
const npm = Object.entries(lock.packages)
  .filter(([path, entry]) => path.startsWith("node_modules/") && !entry.dev && !entry.optional)
  .map(([path, entry]) => {
    const dir = join(root, path);
    const files = readdirSync(dir).filter((f) => /^(licen[sc]e|copying)/i.test(f));
    if (files.length === 0) throw new Error(`${path} has no license file`);
    const texts = files.map((f) => readFileSync(join(dir, f), "utf8").trim()).join("\n\n");
    return `--------------------------------------------------------------------------------\n${path.slice("node_modules/".length)} ${entry.version} (npm), ${entry.license}\n\n${texts}\n`;
  });

const header = `TuxRead third-party licenses

TuxRead itself is free software under the MIT or the Apache-2.0 license (LICENSE-MIT,
LICENSE-APACHE). It is built with the components below; each license text follows the
components it covers. Their sources are on https://crates.io (Rust crates) and
https://www.npmjs.com (npm packages), at the versions given.
`;
writeFileSync(out, `${header}${rust}\n${npm.join("\n")}`.replace(/\r\n/g, "\n"));
console.log(`wrote ${out}: ${rust.split("\n---").length - 1} Rust license blocks, ${npm.length} npm packages`);
```

```powershell
# and exits. WEBVIEW2_BROWSER_EXECUTABLE_FOLDER pointing at an empty folder makes the runtime
```

### Task 4: Copy in full chunks, and two manifest comments

Phase 1's final review: copy-out writes one filesystem block per call, 4 KiB on most ext4 volumes, because `ext4-view`'s `read` returns at most one block. `Copier::pump` reads into a `CHUNK` (1 MiB) buffer but writes whatever one read gave. On NTFS, and over a network share even more, a large file then costs 256 writes per MiB instead of one.

The review also noted two comments in `Cargo.toml`:
- one counts "two fixes" in the vendored `ext4-view`, which now has six;
- nothing warns that `panic = "abort"` would turn the engine's panic guard into a crash.

**Files:**
- Modify: `crates/core/src/copy.rs`, `Cargo.toml`

**Interfaces:**
- Consumes (Phase 1): `Copier::pump(&mut self, reader: &mut dyn Read, file: &mut File, mtime: Option<Timestamp>) -> io::Result<bool>` and `const CHUNK: usize = 1 << 20` in `crates/core/src/copy.rs`.

```ts
/** `text` as a folder path: outer spaces go, and so do the quotes that Explorer's
 *  "Copy as path" puts around a path. */
export function folderPath(text: string): string {
  const trimmed = text.trim();
  const quoted = trimmed.length >= 2 && trimmed.startsWith('"') && trimmed.endsWith('"');
  return quoted ? trimmed.slice(1, -1).trim() : trimmed;
}
```

````markdown
# TuxRead

TuxRead lets you browse and copy files from Linux disks and disk images on Windows. It only
reads: it never writes to a disk or an image. It continues the idea of
[ext2read](https://github.com/mregmi/ext2read) by Manish Regmi.

Version 0.1 reads ext2, ext3 and ext4, inside GPT or MBR partition tables (logical partitions
included) or on a disk with no table. It recognizes LUKS, LVM, Btrfs and XFS and labels them
"supported in a later version", and it labels Windows filesystems as such instead of misreading
them.

## Download

Get TuxRead from [GitHub Releases](https://github.com/PowerUserZ/tuxread/releases). Each release
has, for 64-bit Intel/AMD (x64) and ARM64 PCs:

- `TuxRead-<version>-<arch>-setup.exe`: an installer for your account only, with no
  administrator rights needed. If the Microsoft Edge WebView2 Runtime is missing, it downloads
  and installs it.
- `TuxRead-<version>-<arch>-portable.zip`: `TuxRead.exe` and the command-line `tuxread-cli.exe`,
  to run from any folder. The window needs the WebView2 Runtime, which Windows 11 includes;
  without it, TuxRead says where to get it.
- `TuxRead-<version>-<arch>.sha256`: the files' SHA-256 checksums.

Releases are not code-signed yet (see the code signing policy below), so Windows SmartScreen may
warn the first time. Choose "More info", then "Run anyway".

## Using it

- **Disk images** (raw `.img` files): choose "Open image…".
- **Disks** are listed with a lock. Select one to read it: Windows asks once per session for
  administrator approval. Only a small helper runs elevated; it reads sectors and nothing else.
- Select files and folders, then "Copy to…" (or Ctrl+C) to copy them to a folder on Windows.
  A report lists what was copied, renamed, skipped (such as symbolic links) or failed.
- "Copy diagnostics" puts a summary of your disks and what TuxRead found on them on the
  clipboard, without file names or paths, for a bug report.

The window is in English and Turkish; it follows the Windows language, and About lets you choose.

## Command line

```
tuxread-cli disks                                 list the disks
tuxread-cli probe <source>                        what is on a disk or image
tuxread-cli ls <source> <volume> [path]           list a folder
tuxread-cli cp <source> <volume> <path> <folder>  copy out
```

`<source>` is an image file or `disk:N`, and `<volume>` is the `#number` that `probe` prints.
````

```powershell
# Checks one architecture's release files made by scripts/package.ps1 (spec §9):
# - the checksums match;
# - the zip holds exactly the program, the CLI, the README and the license files;
# - both executables are built for the architecture and carry ProductName "TuxRead" and the
#   release's version, as the installer does;
# - the license file names the window's and the engine's components;
# - the installer asks for no administrator rights.
# With -Install it also installs silently into a folder with spaces and non-ASCII letters (as in
# a user profile named "Şükrü Yılmaz"), checks the installed files, starts the installed program,
# and uninstalls again. That changes the current user's programs: run -Install in CI, or on a
# machine where that is fine.
# Usage: scripts/check-release.ps1 -Arch x64|arm64 -Dir <folder> [-Install]
param(
    [Parameter(Mandatory = $true)][ValidateSet('x64', 'arm64')][string]$Arch,
    [Parameter(Mandatory = $true)][string]$Dir,
    [switch]$Install
)
$ErrorActionPreference = 'Stop'
# .NET calls below resolve a relative path against the process's folder, not PowerShell's.
$Dir = (Resolve-Path $Dir).Path
$root = Split-Path $PSScriptRoot
$version = (Get-Content "$root\package.json" -Raw | ConvertFrom-Json).version
$name = "TuxRead-$version-$Arch"
$machine = @{ x64 = 0x8664; arm64 = 0xAA64 }[$Arch]
$failures = [System.Collections.Generic.List[string]]::new()
function Check([bool]$ok, [string]$what) { if ($ok) { "ok    $what" } else { "FAIL  $what"; $failures.Add($what) } }

# The machine type in a PE file's header.
function Machine([string]$path) {
    $bytes = [System.IO.File]::ReadAllBytes($path)
    $pe = [BitConverter]::ToInt32($bytes, 0x3C)
    [BitConverter]::ToUInt16($bytes, $pe + 4)
}

function Release-Exe([string]$path, [string]$what) {
    $info = (Get-Item $path).VersionInfo
    Check ($info.ProductName -eq 'TuxRead') "$what has ProductName TuxRead (got '$($info.ProductName)')"
    Check ($info.ProductVersion -eq $version) "$what has version $version (got '$($info.ProductVersion)')"
}

$setup = "$Dir\$name-setup.exe"
$zip = "$Dir\$name-portable.zip"
foreach ($line in Get-Content "$Dir\$name.sha256") {
    $hash, $file = $line -split '  ', 2
    Check ((Get-FileHash "$Dir\$file" -Algorithm SHA256).Hash -eq $hash) "checksum of $file"
}
Release-Exe $setup 'the installer'
# A per-user installer runs as the user who starts it; Windows shows no UAC prompt for it.
$text = [System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($setup))
Check ($text.Contains('requestedExecutionLevel level="asInvoker"')) 'the installer asks for no administrator rights'

$unzipped = Join-Path ([System.IO.Path]::GetTempPath()) "$name-check"
Remove-Item -Recurse -Force $unzipped -ErrorAction SilentlyContinue
Expand-Archive $zip $unzipped
$files = (Get-ChildItem $unzipped | ForEach-Object Name | Sort-Object) -join ', '
Check ($files -eq 'LICENSE-APACHE, LICENSE-MIT, README.md, THIRD-PARTY-LICENSES.txt, tuxread-cli.exe, TuxRead.exe') "the zip holds the program, the CLI, the README and the licenses (got $files)"
foreach ($exe in 'TuxRead.exe', 'tuxread-cli.exe') {
    Release-Exe "$unzipped\$exe" $exe
    Check ((Machine "$unzipped\$exe") -eq $machine) "$exe is built for $Arch"
}
$licenses = Get-Content "$unzipped\THIRD-PARTY-LICENSES.txt" -Raw
foreach ($component in 'react 19', 'ext4-view', 'tauri', 'gptman', 'mbrman') {
    Check ($licenses -match [regex]::Escape($component)) "THIRD-PARTY-LICENSES.txt covers $component"
}
Remove-Item -Recurse -Force $unzipped

if ($Install) {
    $installed = Join-Path ([System.IO.Path]::GetTempPath()) 'Şükrü Yılmaz\TuxRead'
    # NSIS takes /D= last and unquoted, spaces included.
    $process = Start-Process $setup -ArgumentList '/S', "/D=$installed" -PassThru -Wait
    Check ($process.ExitCode -eq 0) "the installer runs silently, per user (exit $($process.ExitCode))"
    foreach ($file in 'TuxRead.exe', 'THIRD-PARTY-LICENSES.txt', 'LICENSE-MIT', 'LICENSE-APACHE') {
        Check (Test-Path "$installed\$file") "the installation has $file"
    }
    $app = Start-Process "$installed\TuxRead.exe" -PassThru
    for ($i = 0; $i -lt 100 -and -not $app.HasExited -and $app.MainWindowTitle -ne 'TuxRead'; $i++) {
        Start-Sleep -Milliseconds 200
        $app.Refresh()
    }
    Check ($app.MainWindowTitle -eq 'TuxRead') 'the installed TuxRead opens its window'
    if (-not $app.HasExited) { Stop-Process -Id $app.Id -Force; $app.WaitForExit() }
    $process = Start-Process "$installed\uninstall.exe" -ArgumentList '/S' -PassThru -Wait
    Check ($process.ExitCode -eq 0) "the uninstaller runs silently (exit $($process.ExitCode))"
    # The uninstaller copies itself away and finishes in the background.
    for ($i = 0; $i -lt 50 -and (Test-Path "$installed\TuxRead.exe"); $i++) { Start-Sleep -Milliseconds 200 }
    Check (-not (Test-Path "$installed\TuxRead.exe")) 'the uninstaller removes TuxRead.exe'
}

if ($failures.Count -gt 0) { throw "$($failures.Count) check(s) failed" }
'all release checks passed'
```

```powershell
# Assembles one architecture's release files (spec §9) from a release build: the NSIS installer,
# a portable zip, and their SHA-256 checksums in sha256sum format. Build first with
#   node scripts/third-party-licenses.mjs THIRD-PARTY-LICENSES.txt
#   npx tauri build --config src-tauri/tauri.release.json
#   cargo build --locked --release -p tuxread-cli

param(
    [Parameter(Mandatory = $true)][ValidateSet('x64', 'arm64')][string]$Arch,
    [Parameter(Mandatory = $true)][string]$Out
)
$ErrorActionPreference = 'Stop'
$root = Split-Path $PSScriptRoot
$version = (Get-Content "$root\package.json" -Raw | ConvertFrom-Json).version
$built = "$root\target\release"
$name = "TuxRead-$version-$Arch"
New-Item -ItemType Directory -Force $Out | Out-Null
# .NET calls below resolve a relative path against the process's folder, not PowerShell's.
$Out = (Resolve-Path $Out).Path

Copy-Item "$built\bundle\nsis\TuxRead_${version}_$Arch-setup.exe" "$Out\$name-setup.exe"

$stage = Join-Path ([System.IO.Path]::GetTempPath()) "$name-portable"
Remove-Item -Recurse -Force $stage -ErrorAction SilentlyContinue

Copy-Item "$built\TuxRead.exe", "$built\tuxread-cli.exe", "$root\README.md", "$root\LICENSE-MIT", "$root\LICENSE-APACHE", "$root\THIRD-PARTY-LICENSES.txt" $stage
Compress-Archive -Path "$stage\*" -DestinationPath "$Out\$name-portable.zip" -Force
Remove-Item -Recurse -Force $stage

$sums = foreach ($file in "$name-setup.exe", "$name-portable.zip") {
    '{0}  {1}' -f (Get-FileHash "$Out\$file" -Algorithm SHA256).Hash.ToLowerInvariant(), $file
}
[System.IO.File]::WriteAllText("$Out\$name.sha256", ($sums -join "`n") + "`n")
Get-ChildItem $Out -Filter "$name*" | ForEach-Object { '{0,12:N0}  {1}' -f $_.Length, $_.Name }
```

### Task 9: The CI workflow

Spec §7.6:
- **Linux** generates the corpus, cached by the hash of its scripts, and uploads it as an artifact.
- **Windows x64** runs `cargo fmt --check`, `cargo clippy`, `cargo test` with the corpus, the frontend type-check and build, and `cargo deny check`.
- **§7.4's real-disk test:** "a VHDX is attached as a physical disk … and read end to end through `WinDisk` and the helper". Phase 2 refined it to a fixed VHD, attached with `Mount-DiskImage`.

The window gets two more checks: the WebView2 check (Task 3) and the smoke test.

The runner's account is an administrator with UAC off, so every process on it is elevated. That has three consequences:
- The helper test starts its helper without a prompt.

```yaml
# Fuzzing (spec §7.3): every night each target runs for 20 minutes; a manual run takes the
# length as input (the v0.1 release gate is one hour each, spec §8). A crash fails the job and
# keeps the input that caused it as an artifact.
name: Fuzz

on:
  schedule:
    - cron: "17 2 * * *"
  workflow_dispatch:
    inputs:
      seconds:
        description: Seconds per target
        default: "1200"

permissions:
  contents: read

env:
  CARGO_TERM_COLOR: always

jobs:
  fuzz:
    name: ${{ matrix.target }}
    runs-on: ubuntu-24.04
    timeout-minutes: 90
    strategy:
      fail-fast: false
      matrix:
        target: [part, probe, ext]
    steps:
      - uses: actions/checkout@v7
      - run: sudo apt-get update && sudo apt-get install -y e2fsprogs fdisk
      - run: rustup toolchain install nightly --profile minimal --no-self-update
      - uses: Swatinem/rust-cache@v2
        with:
          workspaces: fuzz
      - run: cargo install cargo-fuzz --locked --version 0.13.2
      - name: Seed inputs
        run: bash scripts/make-fuzz-seeds.sh
      - name: Fuzz
        working-directory: fuzz
        run: cargo +nightly fuzz run ${{ matrix.target }} corpus/${{ matrix.target }} -- -max_len=4194304 -max_total_time=${{ inputs.seconds || '1200' }} -rss_limit_mb=2048
      - if: failure()
        uses: actions/upload-artifact@v7
        with:
          name: fuzz-${{ matrix.target }}-artifacts
          path: fuzz/artifacts
```

Notes:
- **`timeout-minutes: 90`** leaves room for building and seeding around a one-hour run.
- **`-max_len=4194304`** lets inputs reach the 4 MiB the seeds need. Smaller inputs cannot hold a GPT and an ext4 superblock at their real offsets.
- **`-rss_limit_mb=2048`** is the memory limit of §7.3.
